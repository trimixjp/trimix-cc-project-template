# /ai-team-resume — エスカレーション後の再開

あなたはAIチームのオーケストレーターです。人間が対応を完了したチケットを検出し、ワークフローを続きから再開してください。

## 引数

```
/ai-team-resume [チケット番号またはURL]
```

チケット番号またはURLが渡された場合は、そのチケットを直接調査してステップ4へ進んでください。
省略された場合はステップ1から自動検出します。

## ステップ1: 再開対象チケットの検索（引数なしの場合）

以下の条件を満たすチケットを検索します：

**条件:**
- チケットがオープン状態
- `escalated:human` ラベルが**付いていない**（人間が外した）
- コメント履歴に `🚨 エスカレーション` を含むコメントがある
- そのコメントより後に、AIエージェント以外のコメントがある（人間の返答）

**人間コメントの判定:** 先頭行がAIコメント絵文字リスト（正典は `/ai-team-watch` の「AIコメント判定」節）のいずれかで始まらないコメントを人間の返答とみなします。リストを参照できない場合は「先頭が絵文字＋半角スペースで始まらないコメント」を人間の返答とみなしてください。

```bash
npx @trimix/ai-team ticket list --state open
```

取得した各チケットのコメントを確認：
```bash
npx @trimix/ai-team ticket view <番号>
```

## ステップ2: 対象チケットが見つからない場合

```
ℹ️  再開待ちのチケットは見つかりませんでした。

エスカレーション済みチケットを再開するには：
1. 該当チケットにコメントでAIへの指示を記録してください
2. `escalated:human` ラベルを外してください
3. 再度 /ai-team-resume を実行してください
```

## ステップ3: 対象チケットが複数ある場合

候補チケットを以下のフォーマットの番号付き一覧で提示し、再開するチケットを選択するよう求めてください。

```
🔄 再開待ちのチケットが複数見つかりました。再開する番号を選択してください：

  [1] #42: ログインAPIの修正（ラベル: backend:reviewer）
  [2] #57: READMEの更新（ラベル: content:writer）
```

選択されたチケット番号でステップ4へ進んでください。

## ステップ4: 再開対象チケットの状態確認

対象チケットのコメント履歴を全件読み込み、以下を確認します：

```bash
npx @trimix/ai-team ticket view <番号>
```

| 確認項目 | 参照先 |
|---------|--------|
| どのエージェントのどのステップで停止したか | エスカレーションコメント（`🚨 エスカレーション`）の直前のコメント |
| エスカレーション理由 | `🚨 エスカレーション` コメントの「エスカレーション理由」セクション |
| 人間の判断内容 | エスカレーションコメント以降の人間コメント |
| 再開すべき次のステップ | ワークフロー定義の `on_escalation.next` または停止したステップの `on_complete.next` |

### return_to_previous の復帰手順

human-escalator ステップの `on_complete.next` が `return_to_previous`（エスカレーション元のステップに戻る）の場合は、以下の手順で復帰先を決定します。

1. `🚨 エスカレーション` コメント内の構造化フィールド **`エスカレーション元ステップ: <ステップID>`** を読み取る
2. workflow.yml から該当するステップIDの定義を探し、そのステップから再開する

**フィールドが存在しない場合（旧形式のエスカレーションコメント）:**

以下の決定表で復帰先を決定します（上から順に評価し、最初に該当した行を採用）。

| # | 条件 | 復帰先 |
|---|------|--------|
| 1 | チームステップのラベル（`<チーム>:<ステップ>` 形式）がちょうど1つ付いている | そのラベルに対応するステップ |
| 2 | 上記以外で、コメント履歴に `⏭️ 次のアクション:` 行がある | **最後の** `⏭️ 次のアクション:` 行に記載されたステップ |
| 3 | どちらでも判定できない | ユーザーに復帰先ステップを確認する |

採用した行番号と根拠を再開コメント（ステップ5）に記録してください。

## ステップ5: 再開コメントの投稿

```
🔄 エスカレーション解決 — ワークフローを再開します

## 人間の判断
（人間のコメント内容を引用または要約）

## 採用する方針
（決定した方針と根拠）

## 再開ステップ
（再開するエージェント名とステップ名。旧形式コメントから復帰先を推定した場合は推定根拠も記載）
```

## ステップ6: ワークフローの再開

担当チームのワークフロー定義を読み込み、再開ステップのエージェント定義を読み込んで動作を再開します。

```
.claude/teams/<チーム>/workflow.yml の再開ステップ
→ .claude/teams/<チーム>/agents/<エージェント>.md を読み込む
→ 人間の判断をコンテキストとして持ちつつエージェントとして動作
```

### 再開前の検証（エージェント動作を開始する前に実施）

```bash
npx @trimix/ai-team ticket view <番号>
```

- [ ] `escalated:human` ラベルが付いていない（残っている場合は再開せず、人間にラベルを外してもらうよう案内して停止する）
- [ ] 再開ステップのラベル（`<チーム>:<ステップ>`）が付いている（付いていない場合は `npx @trimix/ai-team ticket edit <番号> --add-label "<チーム>:<ステップ>"` で付与してから再開する）
- [ ] ステップ5の再開コメントが投稿されている

## gh コマンド失敗時のフォールバック

`gh` コマンドが失敗した場合は、失敗を無視して先に進んではいけません。

1. **1回だけリトライする**（一時的な失敗の可能性があるため）
2. リトライでも失敗した場合は、**実行すべきコマンドをそのままユーザーに提示して停止**する
