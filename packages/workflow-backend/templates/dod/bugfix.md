# DOD（Definition of Done）— バグ修正

> **対象**: 不具合の調査・修正
> **Contributor がクローズ前にこのチェックリストで完了を判断します**

---

## ✅ バグの特定・再現

- [ ] 不具合の再現手順が Issue に記載されている
- [ ] 期待する動作と実際の動作の差異が明確にされている
- [ ] 影響範囲（どの環境・バージョン・条件で発生するか）が記録されている
- [ ] 根本原因（root cause）が Tech-Lead コメントに明記されている

## ✅ 修正実装

- [ ] 根本原因を解決する修正が行われている（症状の抑制ではない）
- [ ] 変更ファイル一覧が Implementer のコメントに列挙されている
- [ ] 修正により他の機能への副作用が発生していない
- [ ] 一時的な回避策（workaround）ではなく恒久的な修正である
  - 一時的な回避策の場合は理由をコメントに明記し、別 Issue を作成済み

## ✅ テスト

- [ ] バグを再現するリグレッションテストが追加されている
- [ ] 修正後にリグレッションテストが通過している
- [ ] 既存テストがすべて通過している
- [ ] 同様のバグパターンが他の箇所に存在しないことを確認した旨のコメントがある

## ✅ コードレビュー

- [ ] Reviewer によるレビューが完了し「合格」判定がある
- [ ] 指摘された CRITICAL / HIGH 件数が0件
- [ ] 差し戻しがあった場合、全件対応済みのコメントがある

## ✅ PR・マージ

- [ ] PR が作成されている
- [ ] PR 本文に「修正内容・根本原因・テスト手順」が含まれている
- [ ] 人間が PR を承認・マージ済み

## ✅ インシデント確認

- [ ] 本バグが本番環境で発生した場合、インシデントレポートの作成要否を判断した
  - 本番障害に該当 → `.claude/incidents/` への記録を Contributor が実施
  - 開発環境のみ → 「インシデント対象外」とコメント

---

**完了判定**: 上記すべての項目が ✅ であることを Contributor が確認してから Issue をクローズします。
