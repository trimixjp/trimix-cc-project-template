# DOD（Definition of Done）— コードレビュー

> **対象**: 既存コードのレビュー依頼（リファクタリング評価・品質監査等）
> **Contributor がクローズ前にこのチェックリストで完了を判断します**

---

## ✅ レビュー準備

- [ ] レビュー対象のスコープ（ファイル・モジュール・PR）が Issue に明記されている
- [ ] レビュー目的（品質・セキュリティ・パフォーマンス・可読性等）が明記されている
- [ ] Tech-Lead によるレビュー方式の判断コメントが存在する
  - シングルレビュー or ダブルレビューの判断根拠が記載されている

## ✅ レビュー実施

- [ ] 指定された Reviewer が全スコープをレビュー済み
- [ ] 各指摘事項に重大度（CRITICAL / HIGH / MEDIUM / LOW）が明記されている
- [ ] ダブルレビューの場合:
  - [ ] Reviewer-A と Reviewer-B が独立してレビュー済み
  - [ ] クロスレビューで両者の意見が照合され最終判定が出ている

## ✅ 指摘事項の対応

- [ ] CRITICAL 件数: 0件（または全件対応済みで再レビュー「合格」あり）
- [ ] HIGH 件数: 0件（または対応済みコメントあり）
- [ ] MEDIUM 件数: 対応または「未対応の理由」がコメントに明記されている
- [ ] LOW 件数: 対応または「承認済みの未対応」としてコメントに記録されている

## ✅ 成果物

- [ ] レビュー結果サマリーがコメントに記録されている
  - 指摘件数（重大度別）
  - 対応件数と未対応件数
  - 全体評価（合格 / 要修正 / 不合格）
- [ ] リファクタリングが必要な場合は新たな Issue が作成されている

---

**完了判定**: 上記すべての項目が ✅ であることを Contributor が確認してから Issue をクローズします。
