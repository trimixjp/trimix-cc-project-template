# /ai-team configure — ワークフロー設定ウィザード

引数: `/ai-team configure <team_id>`

あなたはワークフロー設定ウィザードです。以下の手順でユーザーと会話しながら `.claude/teams/<team_id>/workflow.yml` を生成・保存してください。各ステップで `AskUserQuestion` ツールを使って質問し、回答を受け取ってから次のステップに進んでください。

---

## ステップ0: チームIDの確認と現状表示

### チームIDの確認

引数として `<team_id>` が渡されている場合はそれを使用します。渡されていない場合は `AskUserQuestion` で選択させてください。

### ディレクトリの確認

Bash ツールで確認してください：

```bash
ls .claude/teams/<team_id>/
```

ディレクトリが存在しない場合はエラーを表示して終了してください：

```
❌ .claude/teams/<team_id>/ が存在しません。
先に /ai-team setup または /ai-team install <team_id> を実行してください。
```

### 現在のワークフローを表示

Read ツールで既存の `workflow.yml` を読み込んでください：

```
.claude/teams/<team_id>/workflow.yml
```

ファイルが存在する場合は、その内容をユーザーに表示してください：

```
📄 現在の workflow.yml:
──────────────────────────────────
<workflow.yml の内容>
──────────────────────────────────
```

ファイルが存在しない場合は「現在 workflow.yml はありません（新規作成します）」と表示してください。

### 新規作成 or 編集の選択

`AskUserQuestion` で確認してください：

> **どちらで進めますか？**
>
> [1] 既存の設定をベースに編集する（現在の設定を維持しながら変更・追加・削除）
> [2] 新規作成する（現在の workflow.yml をすべて置き換える）

ファイルが存在しない場合は自動的に「新規作成」として進んでください。

---

## ステップ1: エージェント一覧の取得

Bash ツールで利用可能なエージェントを取得してください：

```bash
ls .claude/teams/<team_id>/agents/*.md 2>/dev/null | xargs -I{} basename {} .md
```

取得したエージェント名を以降の選択肢として使用します。

---

## ステップ2: ステップの構成を決める

### 「新規作成」の場合

利用可能なエージェント一覧を見せながら、`AskUserQuestion` で確認してください：

> **ワークフローに含めるエージェントを選択してください（複数選択可）**
>
> ワークフローの各ステップはエージェントが担当します。
> 実行順に選択してください。
>
> 利用可能なエージェント:
>   [1] <agent_1>
>   [2] <agent_2>
>   ...
>
> （複数選択可。番号をカンマ区切りで入力してください）

選択されたエージェントの順番でステップを構成します。
**ステップIDはエージェント名と同じに自動設定します**（例: `editor-in-chief`）。

### 「既存を編集」の場合

現在のステップ一覧を表示して、メニューを提示してください：

```
📋 現在のステップ一覧:
  [1] <step_id> (agent: <agent>)
  [2] <step_id> (agent: <agent>)
  ...
```

`AskUserQuestion` で操作を選択させてください：

> **何をしますか？**
>
> [1] ステップを追加する
> [2] ステップを変更する
> [3] ステップを削除する
> [4] ステップの順序を変更する
> [5] 完了（設定内容の確認へ進む）

この操作メニューを、ユーザーが「5: 完了」を選ぶまで繰り返してください。

#### 操作1: ステップを追加する

`AskUserQuestion` で確認してください：

> **追加するエージェントを選択してください：**
>
>   [1] <agent_1>
>   [2] <agent_2>
>   ...
>
> **どこに追加しますか？**
>   [1] 先頭に追加
>   [2] 末尾に追加
>   [3] <既存ステップ名> の後に追加
>   ...

ステップIDはエージェント名を自動設定します。同じエージェントが既に存在する場合は末尾に `-2` を付けます（例: `reviewer-2`）。

#### 操作2: ステップを変更する

`AskUserQuestion` で変更するステップを選ばせてください：

> **変更するステップを選択してください：**
>
>   [1] <step_id> (agent: <agent>)
>   [2] <step_id> (agent: <agent>)
>   ...

選択後、そのステップの詳細設定（ステップ3）に進んでください。

#### 操作3: ステップを削除する

`AskUserQuestion` で削除するステップを選ばせてください。選択後、確認してから削除してください。

#### 操作4: 順序を変更する

`AskUserQuestion` で移動するステップと移動先を選ばせてください。

## ステップ3: 各ステップの詳細設定

ステップ2で「新規作成」または「既存を変更」を選んだステップについて、詳細を設定します。

### 3-1: label と description

`AskUserQuestion` で確認してください：

> **ステップ `<step_id>`（agent: `<agent>`）の基本設定**
>
> 1. **label**（デフォルト: `<prefix>:<agent>`）
>    GitHub Issue に表示されるラベル名です
> 2. **description**（省略可）
>    このステップが何をするかの説明です
>
> スラッシュ区切りで入力してください（例: `content:editor-in-chief / 方針決定とResearcher要否の判断`）
> 省略した場合はデフォルト値が使われます。

### 3-2: 完了後の動作

`AskUserQuestion` で確認してください：

> **`<step_id>` が完了したら次に何をしますか？**
>
> [1] 次のステップへ進む
> [2] 条件によって分岐する（例: 変更規模によってシングル/ダブルレビューを切り替える）
> [3] ここで終了（Issueをクローズする）

#### 選択肢1: 次のステップへ

`AskUserQuestion` で次のステップを選ばせてください。現在のステップ一覧を番号付きで表示してください。

#### 選択肢2: 条件分岐

条件を1つずつ追加します。ユーザーが「完了」を選ぶまで繰り返してください。

各条件について `AskUserQuestion` で確認してください：

> **条件の設定**（これまでの条件: <追加済み条件名>）
>
> 1. **条件名**（例: `single-review`、`double-review`）または「完了」
> 2. **説明**（例: 「変更ファイル数が5未満の場合」）
> 3. **判定基準**（スラッシュ区切りで複数入力可）
>    例: `変更ファイル数が5未満 / 認証関連の変更なし`
> 4. **この条件の次ステップ**（複数の場合はカンマ区切りで → 並列実行になります）

#### 選択肢3: Issueをクローズ

`on_complete.action: close_issue` を設定します。追加入力は不要です。

### 3-3: 差し戻し・エスカレーション・並列設定

`AskUserQuestion` で一括確認してください：

> **`<step_id>` の追加設定（不要なものはスキップ可）**
>
> [1] 差し戻し設定を追加する（レビュー不合格時などに前のステップへ戻す）
> [2] エスカレーション設定を追加する（判断できない時に人間へ依頼する）
> [3] 並列実行設定を追加する（別のステップと同時進行する）
> [4] 完了待ち設定を追加する（複数ステップの完了を待ってから開始する）
> [5] 追加設定なし（次のステップへ）
>
> （複数選択可）

選択された項目についてのみ、続けて詳細を確認してください。

**差し戻し設定：**

> - **差し戻しトリガー**（デフォルト: `差し戻し`）: コメントにこの文字列が含まれると発動します
> - **差し戻し先**: どのステップに戻りますか？（ステップ一覧から選択）

**エスカレーション設定：**

> - **エスカレーション先**: どのステップに引き継ぎますか？（通常は `human-escalator`）

**並列実行設定：**

> - **並列実行する相手のステップ**: どのステップと同時進行しますか？

**完了待ち設定：**

> - **待つステップ**: どのステップの完了を待ちますか？（複数選択可）

## ステップ4: YAML生成・プレビュー・保存

### YAML の生成

収集した情報をもとに以下の形式でYAMLを生成してください。

```yaml
name: <name>
description: <description>

labels:
  prefix: "<prefix>"

steps:

  - id: <step_id>
    agent: <agent>
    label: "<label>"
    description: <description>        # 空の場合は省略
    on_complete:
      next: <next_step_id>

  - id: <step_id>
    agent: <agent>
    label: "<label>"
    parallel_with: <step_id>          # 設定がある場合のみ
    requires: [<step_a>, <step_b>]    # 設定がある場合のみ
    on_complete:
      next: <next_step_id>
    on_rework:                        # 設定がある場合のみ
      trigger: "<trigger>"
      next: <step_id>
    on_escalation:                    # 設定がある場合のみ
      next: <step_id>

  - id: <step_id>
    agent: <agent>
    label: "<label>"
    conditions:                       # on_complete の代わり（排他）
      - id: <condition_id>
        description: <description>
        criteria:
          - <criterion_1>
          - <criterion_2>
        next: <step_id>               # 単一
        # next: [<a>, <b>]            # 並列の場合

  - id: <step_id>
    agent: <agent>
    label: "<label>"
    on_complete:
      action: close_issue             # 終端ステップ
```

**フォーマットルール:**
- `description` が空の場合はそのフィールドを省略する
- `on_rework`、`on_escalation`、`parallel_with`、`requires` は設定がない場合は省略する
- `conditions` がある場合は `on_complete` を省略する
- `next` が単一の場合は文字列、複数の場合は配列 `[<a>, <b>]` で出力する

生成したYAMLを表示してから `AskUserQuestion` で確認してください：

```

📄 生成される workflow.yml のプレビュー
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
```

> **この内容で保存しますか？**
>
> [1] 保存する
> [2] キャンセル

「キャンセル」の場合はウィザードを終了してください。

### 保存の実行

`Write` ツールで `.claude/teams/<team_id>/workflow.yml` に保存してください。

保存完了後に表示してください：

```
✅ workflow.yml を保存しました: .claude/teams/<team_id>/workflow.yml

カスタマイズしたい場合:
  - ワークフロー定義の詳細は .claude/docs/workflow-guide.md を参照してください
  - エージェント定義は .claude/teams/<team_id>/agents/ 内の .md ファイルで管理されています
```
