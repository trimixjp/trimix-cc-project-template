# インシデント管理ガイド

このディレクトリは AIチームが学習・参照するインシデント記録を管理します。

---

## ディレクトリ構成

```
incidents/
├── index.yml          # インシデントインデックス（Contributorが自動管理）
├── TEMPLATE.md        # インシデントファイルのテンプレート
├── README.md          # このファイル
└── YYYYMMDD-*.md      # 個別インシデントファイル（Contributorが自動生成）
```

---

## インシデントが記録される条件

Contributor はIssueクローズ時に以下のいずれかに該当する場合、インシデントファイルを作成します。

| 条件 | 例 |
|------|-----|
| 本番障害が発生した | APIが応答不能、データ損失 |
| セキュリティインシデントが発生した | 不正アクセス、権限設定ミス |
| 重大なバグが本番環境に影響した | P1/P2の本番バグ |
| 設定ミス・操作ミスで障害が発生した | Terraform誤操作、DNS設定ミス |
| 再発防止のために記録すべき教訓がある | 類似ミスの防止 |

上記に該当しない場合は「✅ Contributor確認済み — インシデント対象外」とコメントしてIssueをクローズします。

---

## Contributor による自動フロー

### 1. インシデント調査（クローズ時）

```
1. Issueのコメント履歴・ラベル・タイトルを分析
2. 上記の記録条件に照らし合わせて該当判断
3a. 該当する場合 → インシデントファイルを作成 → index.ymlに追記
3b. 該当しない場合 → 「Contributor確認済み」コメントを投稿
```

### 2. インシデントファイルの作成

```
ファイル名: YYYYMMDD-<概要をkebab-case>.md
内容: TEMPLATE.md に従って記載
  - ⛔ やってはいけないこと
  - ⚠️ 注意事項
  - 根本原因
  - タイムライン
  - 再発防止策
```

### 3. index.yml への追記

```yaml
- id: <次の連番>
  date: "YYYY-MM-DD"
  file: "incidents/YYYYMMDD-*.md"
  title: "インシデントの概要タイトル"
  severity: P1 / P2 / P3
  teams: [backend, infra, content]
  issue: <Issue番号>
  keywords: [関連キーワードのリスト]
```

## エージェントによる活用方法

### Tech-Lead / Infra-Lead / Editor-in-Chief（作業開始時）

```
1. index.yml を読み込む
2. Issueのタイトル・ラベル・内容とkeywordsを照合する
3. 関連インシデントが見つかった場合はIssue本文末に注意事項を追記する
```

### Contributor（クローズ時）

```
1. クローズするIssueの内容を分析する
2. インシデント記録条件に該当するか判断する
3. 該当する場合はインシデントファイルを作成しindex.ymlを更新する
```
