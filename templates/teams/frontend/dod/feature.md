# DOD（Definition of Done）— フロントエンド 新機能実装

> **対象**: 新機能の追加・既存機能の拡張（UI・コンポーネント・ページ）
> **Contributor がクローズ前にこのチェックリストで完了を判断します**

---

## ✅ 設計・要件

- [ ] Issue に要件・機能要件・非機能要件が明記されている
- [ ] Frontend-Lead の設計方針コメントが存在する
- [ ] コンポーネント設計方針・状態管理方針が記録されている
- [ ] アクセシビリティ要件が設計方針に含まれている
- [ ] 影響範囲（変更対象のページ・コンポーネント・スタイル）が明確にされている

## ✅ 実装

- [ ] Frontend-Lead の設計方針に従い実装されている
- [ ] 変更ファイル一覧が Developer のコメントに列挙されている
- [ ] ハードコードされた秘密情報・認証情報がない

## ✅ アクセシビリティ

- [ ] WCAG 2.1 AA 基準を満たしている
- [ ] 適切な ARIA 属性が付与されている（role・aria-label・aria-describedby 等）
- [ ] キーボードのみで全機能を操作できる
- [ ] フォーカス管理が適切（フォーカストラップ・フォーカス復元）
- [ ] スクリーンリーダーで操作可能なことを確認している

## ✅ レスポンシブデザイン

- [ ] モバイル（320px〜）で正常に表示される
- [ ] タブレット（768px〜）で正常に表示される
- [ ] デスクトップ（1024px〜）で正常に表示される

## ✅ ブラウザ互換性

- [ ] 対象ブラウザ（プロジェクト定義）で動作確認済み

## ✅ パフォーマンス

- [ ] 不要な再レンダリングが発生していない
- [ ] Core Web Vitals の基準値を満たしている（LCP 2.5秒以下・INP 200ms以下・CLS 0.1以下）
- [ ] 画像が適切に最適化されている（形式・サイズ・遅延読み込み）

## ✅ ビジュアル確認

- [ ] デザイン仕様との差異がないことを確認している
- [ ] デザインシステム・スタイルガイドに準拠している

## ✅ テスト

- [ ] ユニットテスト・コンポーネントテストが実装されている
- [ ] ハッピーパスのテストが通過している
- [ ] エッジケース・エラーケースのテストが網羅されている
- [ ] 既存テストがすべて通過している

## ✅ コードレビュー

- [ ] Reviewer によるレビューが完了し「合格」判定がある
  - シングルレビューの場合: Reviewer コメントに「合格」あり
  - ダブルレビューの場合: Reviewer-A・Reviewer-B のクロスレビューで「合格」あり
- [ ] 指摘された CRITICAL / HIGH 件数が0件
- [ ] 差し戻しがあった場合、全件対応済みのコメントがある

## ✅ PR・マージ

- [ ] PR が作成されている
- [ ] PR 本文に設計方針・変更内容・アクセシビリティ対応・テスト結果が含まれている
- [ ] PR にスクリーンショットが添付されている
- [ ] 人間が PR を承認・マージ済み

## ✅ ドキュメント

- [ ] 新しいコンポーネント・APIの説明が適切にコメントされている
- [ ] README や仕様書の更新が必要な場合は更新されている（なければ「対象外」）

---

**完了判定**: 上記すべての項目が ✅ であることを Contributor が確認してから Issue をクローズします。
