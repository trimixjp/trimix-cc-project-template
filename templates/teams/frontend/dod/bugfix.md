# DOD（Definition of Done）— フロントエンド バグ修正

> **対象**: UI・コンポーネント・ページの不具合調査・修正
> **Contributor がクローズ前にこのチェックリストで完了を判断します**

---

## ✅ バグの特定・再現

- [ ] 不具合の再現手順が チケットに記載されている
- [ ] 期待する動作と実際の動作の差異が明確にされている
- [ ] 発生環境（ブラウザ・OS・デバイス・画面サイズ）が記録されている
- [ ] 根本原因（root cause）が Frontend-Lead コメントに明記されている

## ✅ 修正実装

- [ ] 根本原因を解決する修正が行われている（症状の抑制ではない）
- [ ] 変更ファイル一覧が Developer のコメントに列挙されている
- [ ] 修正により他の機能・コンポーネントへの副作用が発生していない
- [ ] 一時的な回避策（workaround）ではなく恒久的な修正である
  - 一時的な回避策の場合は理由をコメントに明記し、別 チケットを作成済み

## ✅ アクセシビリティ

- [ ] 修正によって WCAG 2.1 AA 準拠が損なわれていない
- [ ] キーボード操作・スクリーンリーダーへの影響がないことを確認済み

## ✅ レスポンシブ・ブラウザ互換

- [ ] 修正が対象ブラウザ・デバイスで動作することを確認済み
- [ ] 修正が各ブレークポイント（モバイル・タブレット・デスクトップ）で正常に表示されることを確認済み

## ✅ テスト

- [ ] バグを再現するリグレッションテストが追加されている
- [ ] 修正後にリグレッションテストが通過している
- [ ] 既存テストがすべて通過している
- [ ] 同様のバグパターンが他のコンポーネント・ページに存在しないことを確認した旨のコメントがある

## ✅ コードレビュー

- [ ] Reviewer によるレビューが完了し「合格」判定がある
- [ ] 指摘された CRITICAL / HIGH 件数が0件
- [ ] 差し戻しがあった場合、全件対応済みのコメントがある

## ✅ PR・マージ

- [ ] PR が作成されている
- [ ] PR 本文に「修正内容・根本原因・テスト手順」が含まれている
- [ ] PR に修正前後のスクリーンショットが添付されている（視覚的バグの場合）
- [ ] 人間が PR を承認・マージ済み

## ✅ インシデント確認

- [ ] 本バグが本番環境で発生した場合、インシデントレポートの作成要否を判断した
  - 本番障害に該当 → `.claude/incidents/` への記録を Contributor が実施
  - 開発環境のみ → 「インシデント対象外」とコメント

---

**完了判定**: 上記すべての項目が ✅ であることを Contributor が確認してから チケットをクローズします。
