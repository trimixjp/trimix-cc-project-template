# PRODUCTION-GUIDE.md — YouTube動画制作チーム 制作憲法

> 本書は YouTube 動画制作チームの**単一情報源（Single Source of Truth）**である。
> 企画・台本・音声・動画組立・公開の全工程で、すべてのエージェント（director / channel-producer /
> scriptwriter / editor / growth-strategist / affiliate / publisher / sns-distributor / monetizer /
> contributor）はここに書かれた基準で判断する。ここに無い判断はチャンネルの voice-guide → 制作エンジン
> repo の CLAUDE.md の順で遡る。
>
> **公開品質の基準は本書だけが定める。** DoD（§9）・権利安全（§10）・メタデータ（§11）・公開規約（§12）に
> 1つでも抵触したら公開しない。

---

## 0. 用語と前提

- **制作エンジン**: 「ai-youtube 型の制作エンジン repo」。共通エンジン（`packages/`）に**1度だけ**実装し、
  チャンネルは `channels/<id>/` 配下の**データ（config）**として表現する。コードをチャンネルごとに
  複製しない。**エンジン repo の絶対パスは Issue またはチャンネル設定で与えられ、本書にハードコードしない。**
- **スキル**: 各工程は規約上のスキル名で呼ぶ（`yt-new-channel` / `yt-plan-month` / `yt-script` /
  `yt-render` / `yt-publish` / `footage-tag`）。
- **CLI 規約**: 動画生成・公開・プレビューは `node <engine>/packages/app/dist/cli.js {render|publish|preview}`
  の形（`<engine>` は与えられたエンジン repo のパス）。
- **成果物**: 音声・動画など重いバイナリは `output/<id>/<episode>/` に出し、git に入れない。
- **台本（ソース）**: `channels/<id>/episodes/NNNN-slug.md`。frontmatter にメタデータ、本文にスクリプト。git 管理。

## 1. 三大原則（制作憲法の核）

すべてのルールはこの3点から導かれる。工程の判断に迷ったら、まずこの原則に照らす。

### ① 台本が土台（全工程の労力の約5割）

- 内容（海外視聴者に有益・正確・出典付き）、構成、そして**ナレと映像・写真の噛み合わせ**まで、
  **「直すところがない」水準に仕上げてからレンダリングに進む。**
- 動画制作は時間もコストも大きく、**台本の粗は全部後工程で倍払いになる。** 10チャンネル × 週3本の
  量産を成立させる基礎は台本の質。
- レンダリング段で「直し場所」が出たら、それは**台本に戻して直す**（レンダラ側の自動分割や LLM 補完で
  ごまかさない）。

### ② 情報が主・デザインは従（最重要）

- 説明動画の**画面テキストは絶対に切り捨てない**（「…」省略禁止）。**テキスト同士を重ねない**。
- **器側が文字に合わせる**（fitFontSize の縮小と折り返しで収める）。クランプ（validate.ts 相当）は
  プロンプト推奨長の約2倍の「安全弁」であり、通常運転で発火させない。
- **レイアウトの綺麗さを理由に情報を削る変更は禁止。**

### ③ 写真は事実そのもの（ナレが指す対象と一致した写真のみ）

- 固有の場所・路線・実物を見せる写真は、**その対象だと確認できたものだけ**使う。
  「駅の話だから駅の写真なら何でもいい」は禁止。
- **一致する写真が無ければ写真を諦めて図解にする。間違った写真は写真なしより悪い。**
- レンダリング後の**写真照合（目視）は必須工程**（§8 ゲートC・§9 DoD）。

#### 実害例（過去に実際に踏んだ）

| 原則 | 実害 |
|---|---|
| ③ 写真不一致 | 銀座線浅草駅の説明に、大阪・心斎橋駅の写真を当ててしまった |
| ② 情報削り | レイアウト都合で画面テキストを「…」省略 → 視聴者が読めない不完全な情報になった |
| ① 台本の粗 | 1スライドのトピックが render 時に台本に無い4枚へ化け、カット境界で空白・重なりが発生（13トピックが56ショットに膨張） |

## 2. パイプライン全体像

### 5段階と工程スキル

```
① 企画         → ② 台本             → ③ TTS                → ④ 動画組立           → ⑤ 公開
  yt-new-channel    yt-script             (yt-render の内部)     yt-render             yt-publish
  yt-plan-month     footage-tag           セグメント個別合成     絵コンテ→確定→still    多言語字幕登録
  (重複防止)        (visual/cues/sources)                        ピクチャーロック       配信カレンダー更新
```

| 段階 | 主担当 | スキル | 主な成果物 |
|---|---|---|---|
| ① 企画 | channel-producer | `yt-new-channel`（立上げ）/ `yt-plan-month`（月次計画） | channel.yaml・glossary・voice-guide・plans/YYYY-MM・エピソードスタブ |
| ② 台本 | scriptwriter | `yt-script` / `footage-tag` | `episodes/NNNN-slug.md`（frontmatter＋本文＋visual/cues/sources） |
| ③ TTS | editor（yt-render 内部） | （`yt-render` が内部実行） | `output/<id>/<episode>/segments/seg_*.mp3`（実測尺） |
| ④ 動画組立 | editor | `yt-render` | storyboard.json・確定写真・slides/*.png・preview.html・動画 |
| ⑤ 公開 | publisher | `yt-publish` | YouTube 動画（privacy:private）・8言語CC・配信カレンダー更新 |

### status 状態機械（frontmatter.status）

台本ファイルの frontmatter `status` が状態機械そのもの。エンジンはこれを見て駆動する。

```
idea → draft → reviewed → rendered → uploaded → published
```

| status | 意味 | 遷移の節目 |
|---|---|---|
| `idea` | スタブ生成済み（重複防止クリア） | 企画で確定 |
| `draft` | 台本執筆完了 | yt-script 完了。配信カレンダーに台本リンク追加 |
| `reviewed` | 品質ゲート通過＋ピクチャーロック承認 | editor 合格＋preview.html ユーザー承認 |
| `rendered` | 動画生成・自己検証完了 | yt-render 完了。配信カレンダーに制作状態更新 |
| `uploaded` | アップロード済み（予約公開待ち含む） | yt-publish 完了。動画リンク＋予約日時を記録 |
| `published` | 公開済み | publish_at 到達後。youtube_video_id 書き戻し |

## 3. チャンネル規約（channel.yaml）

このファイル1枚でチャンネルの挙動が決まる。コードは触らない。エンジンは Zod でパースして書き間違いを
実行前に弾く。

### 全フィールド

| ブロック | フィールド | 意味 |
|---|---|---|
| `channel` | `id` | ディレクトリ名と一致 |
| | `name` | 表示名 |
| | `language` | `ja`/`en` 等。TTS・台本プロンプトの分岐 |
| | `youtube_channel_id` | YouTube チャンネル ID（null 可） |
| | `enabled` | false ならバッチ実行時にスキップ（「今日はこの3chだけ」を1行で制御） |
| `script` | `model` | 台本生成モデル（台本＝Opus 推奨） |
| | `target_minutes` | 尺の目安（基準12分）。ここから文字数を逆算 |
| | `format` | `explainer`/`listicle`/`story`/`news` 等 |
| | `voice_guide` | voice-guide.md へのパス（後述） |
| | `research` | `enabled`＋`provider`（perplexity 等） |
| `voice` | `provider` | `elevenlabs`（英語ch）/ `style-bert-vits2`・`voicevox`（日本語ch）等 |
| | `voice_id` | provider 固有の声 ID |
| | `speed` | 話速 |
| | `params` | provider 固有パラメータ（tts アダプタが吸収・共通化しない） |
| `video` | `composition` | Remotion のコンポジション名 |
| | `resolution` | `1920x1080`（横）/ `1080x1920`（縦） |
| | `theme` | **配色**（`primary`/`accent`/`bg`/`ink`/`font`）。ブランド一貫の単一情報源 |
| | `motion` | `ken-burns`/`veo`/`none` |
| | `bgm` | BGM パス（null 可） |
| | `intro` | ブランドイントロ・案内人識別・CTA 文言 |
| `subtitles` | `model` | 翻訳モデル（**安価モデル＝Haiku** で十分） |
| | `source` | 原本言語（**ja**＝日本語原本が真実の源） |
| | `targets` | 翻訳先言語の配列（後述8言語） |
| | `glossary` | glossary.yaml へのパス（null 可） |
| `upload` | `privacy` | **既定 `private`**（人間確認後に公開・予約公開も private のみ） |
| | `category_id` | 例 19=Travel & Events, 28=Science & Tech |
| | `ai_disclosure` | **既定 false**（§12 の新基準で内容判断） |
| | `tags_strategy` | `from-script`/`manual` |
| | `schedule` | **常に null**（予約はエピソード別 publish_at・§12） |
| `monetization` | （§11 参照） | 開示文・常時アフィリ（always）・プログラム定義（programs） |

### 趣旨・言語・字幕

- **字幕は8言語**を基本とする（訪日インバウンド上位国籍とほぼ一致）:

  `EN · JA · KO · zh-CN · zh-TW · FR · IT · TH`

  - **中国語 = 簡体字（zh-CN）**（大陸向け）／**台湾語 = 繁体字（zh-TW）**（台湾・香港向け）。
    本来の台湾語（台語＝閩南語）は字幕・フォント対応が乏しく非現実的なので繁体字でカバーする。

### テンプレ（video.theme 配色）

- 配色は `video.theme` に集約し、エンジン側にチャンネル名をハードコードしない。
- 例（nihon101）: 藍 `#16314F` / 朱 `#E0533C` / 生成り `#F4EEE2` / 墨 `#1A1D24` / NotoSansJP。
  観光パンフ調にしない・誇張しない上品なモーション。

### 配信スケジュール

- **カデンス例: 週3本**（10ch × 週3本 = 週30本が量産前提）。
- **予約日時はエピソード別 `frontmatter.publish_at`** に持つ（配信計画 plans/YYYY-MM の日付から落とす）。
- **`channel.yaml.upload.schedule` は使わない（null 固定）。** チャンネル単一値だと複数本の同時アップロードで
  全部同じ日時に予約され**大事故**になる（§14 事故源）。

### voice-guide の役割

- 台本の**声・人格・口調**の指示書（別 Markdown。yaml にベタ書きしない）。
- **一人称・口語・本音**を強化（「私は」「正直に言うと」「地元では」）。在住者の信憑性を声で担保する。
- ロボ的・無味なナレは避ける（inauthentic リスク＆人間味喪失）。

## 4. 字幕・多言語

### 真実の源は日本語原本

- **source of truth は日本語原本**（`channels/<id>/episodes/NNNN-*.md` の本文）。
- チャンネルが英語ナレでも、**英語ナレも各言語字幕もすべて日本語原本からの翻訳**である。

### 翻訳は安価モデル（Haiku）

- 字幕＝テキスト翻訳なので極めて安い。**Claude Haiku ＋ Batch（50%引）＋プロンプトキャッシュ**で
  全言語でも月 $1〜2 程度。**コスト理由で言語を削らない。**

### glossary 3分類で固有名詞の綴りを固定

MT（機械翻訳）が最も滑るのが固有名詞。**固有名詞は訳さず、確定した綴りで固定**する。
`glossary.yaml` を翻訳プロンプトに渡し「このリストの語は訳さずこの綴りのまま出力せよ」と指示する。

| 分類 | 意味 | 例 |
|---|---|---|
| `force_all_languages` | ブランド語・番組名・サービス名。**全言語で同一綴り** | Suica, PASMO, JR Pass, omotenashi, ramen, konbini |
| `latin_only_for_western` | 地名等。西欧言語（EN/FR/IT）はローマ字固定、**CJK（JA/KO/zh-CN/zh-TW）は現地表記を許可** | Shibuya, Tokyo, Kyoto, Mount Fuji |
| `season_culture_terms` | 訳さず綴り固定する文化・季節語 | tsuyu, ajisai, depachika, teru teru bozu |

### 逆翻訳QA（back-translation check）

- **手順**: ①固有名詞チェック（決定的・コードで綴り照合）→ ②逆翻訳（Haiku で各言語訳→日本語）→
  ③LLM判定（**日本語原本**と**日本語逆翻訳**を直接比較）。
- source が日本語・逆翻訳も日本語なので、**日本語同士の突き合わせ**になり判定が単純で高精度。
- 検出: 意味のズレ（特に**否定の反転**）・抜け・追加・固有名詞崩れを深刻度付き（critical/minor）で。
- **重大（意味の逆転・固有名詞崩れ）は公開前にブロック**、軽微は記録に留める。

### CC タイムコードはショットタイムライン基準（最重要・全ch共通）

> 字幕がナレより先行して累積ズレする実害から確立した不変条件。

- **字幕（CC）の時刻は「最終動画のショットタイムライン」基準で作る。**
- **narration.mp3（一本撮り音声）のタイムスタンプをそのまま使ってはならない。**
- 理由: 確実同期（§7）の動画は各ショット末尾に無音ポーズが入るため、一本撮り基準だと動画が進むほど
  字幕が**先行**してズレ続ける（16分で数十秒に達する）。
- 正しい作り方:
  1. ショット開始秒 = `storyboard.json` のショット列を render と同じ配置計算で並べた開始フレーム ÷ FPS。
  2. ナレ言語の cue = ショット開始秒 ＋ クリップ内文字タイムスタンプ（クリップ先頭0秒基準）。
  3. 翻訳の cue = 文の累積文字比を**発話スパン列**（ポーズを含まない区間）へ区分線形に配分（`[0, total]` への単純比例は禁止）。
  4. 差し替えは同言語の既存トラックを delete してから insert（再 publish で重複させない）。

## 5. 台本規約

### frontmatter 台帳（ledger）

別途 DB を立てず、Markdown の frontmatter が台帳の行を兼ねる。

| フィールド | 意味 |
|---|---|
| `id` | `<channel>-NNNN` |
| `channel` | チャンネル ID |
| `title` | タイトル（日本語可。英語タイトルは別途 §11） |
| `status` | 状態機械（idea→draft→reviewed→rendered→uploaded→published） |
| `series` / `series_part` | シリーズ名・話数（単発は null） |
| `topic_key` | 正規化した話題キー（重複判定用） |
| `keywords` | タグ（エピソード間で衝突しないもの） |
| `embedding_id` | 重複判定用ベクトル ID |
| `publish_at` | **予約公開日時**（配信計画 plans/ の日付・§12） |
| `youtube_video_id` | アップロード後に書き戻す |
| `affiliates` | その回固有のアフィリ（§11） |
| `ai_disclosure` | その回だけ true にする上書き（§12） |
| `sections` | 章配列（後述） |
| `related` | 関連エピソードへのリンク |

### sections 配列（章 role）

各章は構成上の役割（role）を持つ。リテンション設計（§6・編集文法）の土台。

`hook`（掴み） → `promise`（約束・オープンループ） → `body`（本編） → `midpoint`（中盤の山場） →
`payoff`（約束の回収） → `cta`（次の動画・チャンネル誘導）

- 章タイトルは `sections[].title_en`（無ければ `title`）を使う。YouTube Chapters の章名になる（§11）。

### 台本＝タイムライン（ピクチャーロック）

> 「台本で確認した画面が、そのまま最終動画になる」ことを構造的に保証する。

- **1トピック = 1ショット = 1音声クリップ = 1台本visual。**
- **カット境界は台本の構造のみが決める**（`@section` / `@topic` マーカーと ` ```visual ``` ` ブロック）。
  **秒数による自動分割は禁止。** 1つの @topic の地の文が何文あっても1ショットにまとめる。
- 「スライドが長すぎる／単調」と感じたら、**直し場所は台本**（トピックを2つに割る・cues で段階表示を足す）。
  レンダラ側の自動分割で解決しない（編集判断は人間＝台本に置く）。
- レンダリング経路に**LLM・検索・乱択を入れない**（決定論）。visual の無いトピックは「台本の不備」として
  **警告で顕在化**（黙って LLM 補完しない）。

### マーカー順序

台本本文のマーカーは次の順で書く:

```
@section（章境界・role） → @topic（トピック境界＝ショット境界） → 地の文（ナレ原稿） → ```visual ブロック
```

### 13構造規約の要点（編集文法の台本反映）

- セグメント = **音声合成の単位 ＝ ショットの単位 ＝ 1つの視覚化（型）の単位**（三位一体）。
- 1ショット1アイデア。新情報・新トピック・キーワード・数字・章転換でのみ切る。
- caption に出す語はそのセグメント内で発話されるキーワードに限定（発話同期のため）。
- 章境界には間（短い静止）・章カード・L カット気味の繋ぎを設計（§6）。
- 構成メタ（hook/promise/body/midpoint/payoff/cta）を章に持たせる。

### 尺・分量の上限

| 項目 | 基準 |
|---|---|
| 尺の上限 | **15分**（YouTube の電話確認なし上限。§12） |
| 尺の目標 | **14分**（上限割れの安全マージン） |
| 地の文 | **〜3200字**（target_minutes から逆算した目安） |
| トピック数 | **25〜28トピック上限** |

### コンテンツの濃さ（在住者の信頼）

- **在住者の一人称・本音・一次情報**を必須要素にする。
- 各エピソードに**一次情報を目安3〜5個**（在住者しか言えない店名・駅名・値段・時間帯・手順・地元の常識/本音）。
- 薄い一般論だけの段落は人間編集パスで削る（commodity 排除）。「どのサイトにもある一般論」は watch time を生まない。
- 「ここは観光客向け／地元はこうする」式の踏み込みを各回に1つ入れる。

## 6. 視覚・モーション

### モーショングラフィック主役・実写 footage 脇役

- **動くモーショングラフィックが主役。** トピックを**型（template）**に分類し、データ駆動で動かす。
- **実写 footage は脇役（尺合計の 20〜30%＝2〜3割）。** 型の中に小窓ピクチャーインで挟むか、型と型の間に単独 broll で挟む。
- footage タグがゼロなら全編モーショングラフィックにフォールバック（むしろ自然）。
- 図解だけのフルスクリーンを連続させない（「動く授業スライド」化を防ぐ／inauthentic リスク）。

### 9型（templateType）

| 型 | 用途 |
|---|---|
| `progressive` | 段階変化（同じ対象が次々に変わる・問題→対処） |
| `contrast` | 対比＋否定（海外 vs 日本／Before vs After） |
| `howto` | 手順・操作（触れて→引かれて→開く） |
| `list` | 列挙（持ち物・アプリ・フレーズ） |
| `stat` | 数値強調（金額・期間・時刻） |
| `map` | 地図・位置・地域差（関東 vs 関西） |
| `timeline` | 時系列・制度変更（値上げ・免税変更） |
| `concept` | 定義・概念（meiwaku・omotenashi の説明） |
| `warning` | 注意・禁止・訂正（チップ禁止・古い情報の訂正） |

### 視覚の禁止・制約

- **テキスト量上限を型ごとにスキーマで縛る（`.max` 制約）**。行/項目 ≤ 5（list/progressive）、lines ≤ 4（contrast）、
  pins ≤ 6（map）、points ≤ 5（timeline）。図解ラベルは英語20〜26字程度・キャプションは1行。
- **空カード禁止**: 行0件・空文字は安全なプレースホルダにフォールバック（落とさない）。
- **実物は AI 生成しない**: 実在物（Suica・改札・特定店舗）は実写ストックか**一般化図解**で表す。
  実物デザイン・ロゴは描かず一般化する（無地カード＋"IC"文字 等）。
- **画面ラベルは英語のみ**: `CHECK・確認` のような日英混在禁止。構造ラベル（eyebrow/見出し/badge）は英語限定。
- **焼き込み字幕なし**: 型内テキストは「説明のための図解ラベル・短いキャプション」であって、ナレ全文テロップではない。
  多言語字幕は YouTube CC/SRT で出す。
- アニメは誇張しない（fast take-off / slow landing = ease-out・1セクション1モーメント）。

## 7. 音声・映像の決定的同期

> 「I live in Tokyo のナレが映像から10秒ズレる」を**構造的に根治不能**にする方式。
> ズレは実装バグではなく**多段推定というアーキテクチャの欠陥**。パラメータ調整では治らない。作り方を変える。

### セグメント個別音声合成（推定の全廃）

```
ナレを「同期セグメント」に分割（合成前に確定・@topic/visual 単位）
  → 各セグメントを TTS で個別に合成 → seg_000.mp3 … seg_NNN.mp3
  → 各クリップの実音声尺を ffprobe で実測（durSec[i]）  ◎事実（実測）
  → ショット尺 shotFrames[i] = round(max(audioFrames[i], animMinFrames[i]) × FPS)
  → 各ショットにそのセグメントの音声クリップを 1:1 で配置（Remotion <Series>＋<Audio>）
```

### 不変条件

```
ショット i に貼る音声 = seg_i.mp3 ＋ 末尾無音（shotFrames[i] − audioFrames[i]）
videoDuration = Σ shotFrames[i] ≡ Σ（そのショットに貼った音声＋無音の尺）
∴ 各ショットで映像とそのセグメントの発話が常に同一区間に存在する（1:1・ズレ得ない）
```

### 推定の全廃

- 廃止される推定: ①文字インデックス→秒、②/③日本語→英語の文字比・文番号比写像、④ffmpeg 全文切り、⑤timestamps シフト。
- 同期計算は **`seriesSequencePlans`（render と同じ配置計算）基準**で行う。**naive な累積和（単純な足し上げ）は禁止**（§14 事故源）。
- 型内要素（list 項目・map ピン・howto ステップ）の出現は**クリップ内ローカル秒**（クリップ内文字タイムスタンプ）で解決。
  ショット境界＝クリップ境界なのでショットをまたぐ累積秒が登場しない＝ここでもズレ得ない。
- 映像はナレに先行しない（アニメ最小尺 > クリップ尺なら超過分は静止で待つ）。

## 8. 品質ゲート

公開までに4つのゲートを順に通す。1つでも欠けたら次へ進まない。

### ゲートA — 機械検証ゼロ件

- マーカー位置・宣言整合・visual スキーマの機械検証が**ゼロ件**。
- アンカーアライメント全件採用（ログ確認）・断片クリップなし。

### ゲートB — レビュー指摘解消（editor）

- 編集文法・9型整合のレビュー指摘を解消。
- **同じ型を3連続させない**（型の単調回避）。
- **写真枯渇区間（実写ゼロのトピックが連続する区間）が無い**。
- **有益性**: 在住者の一次情報・独自視点・知識ギャップ型タイトルが満たされている。

### ゲートC — 写真確定とスライド実レンダ（confirm/render）

- 写真を**確定 pin**（`pexels:<id>` / `wikipedia:<記事>` / `commons:<File>` / `file:<名>` で台本に書き戻し）。
  `query` だけの未確定写真を残さない。
- **写真の事実照合 全件目視**（不一致ゼロ。ナレが指す対象と一致するか1枚ずつ確認）。
- 各トピックの図解を **slides/<topicId>.png として実レンダリング**（renderStill）。

### ゲートD — preview.html のユーザー承認（＝ピクチャーロック）

- `preview.html`（確定写真＋スライド実画像をトピック単位で表示）を**ユーザーが承認**する。
- この承認が**ピクチャーロックの単位**。承認したプレビュー = 最終動画（preview と render が同じ台本 visual を 1:1 でショット化）。
- 承認で `status: reviewed` へ。**30本/週でも「台本（preview）OK = 動画OK」**にする（本番動画の全編目視に依存しない）。

## 10. 権利・安全（禁止リスト・絶対遵守）

1. **人物が識別できる写真**をネガティブ・批判的な文脈（炎上・違反・事故）に並べない。
   その話題は図解で表す。ストックフォトの人物は「その話の当事者」ではない。
2. **ロゴ・商標・キャラクター**は図解に描かない（既定）。特定商品・企業を批判する文脈に**その企業のロゴ写真を使わない**。
   写真内に偶然写るのは可。
3. **アニメ・映画等の著作物**は映像・画像・音声を一切使わない（聖地巡礼系は実在の場所の写真と地図のみ）。
4. **BGM** は出所とライセンスを `channels/<id>/assets/` の README に記録してから使う。不明な音源は使わない。
5. **制度・医療・法律・税**は断定せず「2026年◯月時点」「公式サイトで最新確認を」を添える（**時点明記**）。
   渡航・ビザ等は公式リンクを説明欄に置く。
6. **実在店舗・施設**を批判的な文脈で特定店名を出さない（一般化して語る）。

## 11. 収益化・アフィリエイト

### 説明欄の構成（自動生成・決定論）

```
タイトル
→（任意）🛒 アフィリエイト（開示文＋リンク・各リンクに sub_id=<channel>_<episode>）
→（任意）⏱️ Chapters（台本 sections から・先頭0:00・3章以上）
→ 📍 スポット（Google Maps リンク）
→ 画像クレジット（Wikimedia 帰属）
```

- **アフィリエイトは決定論で生成**（`channel.yaml monetization` ＋ `frontmatter.affiliates` を重複なく解決）。
  - **チャンネル共通（常時）**: `monetization.always` のプログラム ID → 全動画の説明欄に常に出る（例: Klook）。
    `programs` に id→`{label, url, subid_param}` を登録。**url が空のプログラムは出力しない**（未開設は雛形として安全）。
  - **動画ごとの追加**: `frontmatter.affiliates` にその回だけの商材（①登録済みプログラム ID 参照、②インラインのアドホックリンク `{label, url, subid_param?}`）。
    **アフィリリンクは自動生成できない**ため、その回固有の商材は**人間が各社ダッシュボードで作って台本に直書き**する。
  - 各 URL に**計測用 sub_id（`<channel>_<episode>`・ハイフンは `_` に正規化）**を付与する。
- **開示文はリンクの直上に必ず置く（FTC 順守）。** 掲載が無い回（解決0件）は開示文も出さない。
- **章（Chapters）は storyboard.json のショット（`durationInFrames`＋`sectionId`）から決定論で生成**。
  セクション初出の開始時刻を章にし、先頭は必ず `0:00`。各章10秒以上に間引き、3章未満なら出さない。章名は `sections[].title_en`。
- **スポットは台本 visual の `spots`（地名・空港・駅・名所）から決定論で Google Maps 検索リンクを生成**（LLM 任せにしない）。
- **数字・事実の出典 URL は説明欄に載せない**（出典はプレビュー HTML に残し編集時の事実確認に使う）。画像クレジットは載せる。

### 伸ばすための規約

- **CTR タイトル**: 英語・**60字以内**・**知識ギャップ型**（「なぜ日本人は◯◯」「観光客がやりがちな◯◯の間違い」）・
  **先頭に主要キーワード**・釣りすぎない（内容で回収できる範囲）。yt-script が候補3本を出しユーザーが選ぶ。
- **視聴維持**: 冒頭30秒で強いフック（イントロは5秒以内 or 廃止）。冒頭で問い/予告を開く **open loop** を作り、
  2〜3分ごとに再提示・一部回収。中盤に山場（ミッドポイント）。
- **チャンネル横断送客**: 関連動画・他チャンネルへ誘導し、ポートフォリオ内で回遊させる。
- **CPM の高い領域**を意識（旅行・金融・テック等は CPM が高い）。
- **複数チャンネルのポートフォリオ**で住み分ける（入門 → 旅行 → 文化 → 専門）。トピック重複を避け、各 ch の角度を尖らせる。

## 12. 公開の規約

- **privacy: private 起点**。自動運用でも公開前に人間が1本見るワンクッションで誤情報・AI臭い回を止める。
  **予約公開（publishAt）は YouTube API 仕様で private のみ可。**
- **予約はエピソード別 `frontmatter.publish_at`**（配信計画 plans/ の日付）。channel.yaml の schedule は null 固定（§3・§14）。
- **多言語 CC 自動登録**: publish が動画アップロード後に全言語（8言語）を自動登録。1言語の失敗は警告して続行（動画アップロードは成功扱い）。

### AI 開示の新基準（既定 false）

- **既定は `channel.yaml upload.ai_disclosure`（既定 false）。**
- YouTube の開示要件（containsSyntheticMedia）は次の**3つに限定**して該当時のみ true:
  1. **実在人物のなりすまし**
  2. **実写の改変**
  3. **フォトリアルな偽場面**
- 図解＋実写そのまま＋（特定人物でない）合成ナレは**いずれも非該当 → 「いいえ」**。説明欄にも開示文は書かない。
- **生成AIでなりすまし/改変実写/偽場面を使う回だけ**、その台本の frontmatter に `ai_disclosure: true` を入れる（エピソード別上書き）。
  publish が自動で「はい」を立てる（手動 Studio 操作は不要）。

### 制約・クォータ

- **15分超は電話番号確認必須**（未確認だとアップロード直後に動画が消える → youtube.com/verify 後に再 publish）。だから尺は15分上限・14分目標（§5）。
- **API クォータ**: 1日10,000 units。**動画アップロード=1600 units ＋ 字幕=400 units × 言語数**（8言語≈3200）。
  → **publish は1日2本が上限**。`quotaExceeded`（403）は **PST 0時（JST 16/17時）にリセット**するまで待つ。字幕は冪等リトライ。
  10ch 週3本ならクォータ増枠申請が必須（先に申請）。
- **API で検証してから成功宣言**: アップロード/字幕登録は API レスポンスで成否を確認してから「成功」と報告する（楽観報告禁止）。

## 13. 制作エンジン規約（抽象化）

- 本チームは **ai-youtube 型エンジン**（共通エンジン `packages/` ＋ チャンネルデータ `channels/<id>/`）の上で動く。
- **エンジン repo のパスは Issue / チャンネル設定で与えられ、本書にハードコードしない。** 以下の `<engine>` は与えられたパスに読み替える。
- 各工程は**スキル**を呼ぶ:

  | スキル | 工程 |
  |---|---|
  | `yt-new-channel` | チャンネル立ち上げ（channel.yaml・glossary・voice-guide・brand・roadmap・YouTube設定） |
  | `yt-plan-month` | 月次配信計画・トピック選定・重複防止・エピソードスタブ |
  | `yt-script` | リサーチ＋台本執筆（visual/cues/sources・在住者一人称・13構造規約） |
  | `yt-render` | TTS（セグメント個別合成）＋絵コンテ＋写真確定＋still＋動画生成＋自己検証 |
  | `yt-publish` | アップロード（private）＋予約公開＋多言語字幕＋API検証＋配信カレンダー更新 |
  | `footage-tag` | 実写素材のタグ付け（footage manifest 整備） |

- **CLI 規約**: `node <engine>/packages/app/dist/cli.js {render|publish|preview}` の形。
- **成果物**: `output/<id>/<episode>/`（動画・`segments/seg_*.mp3` 等）。git に入れない。
- **台本**: `channels/<id>/episodes/NNNN-slug.md`。frontmatter にメタデータ、本文にスクリプト。git 管理。

| 4 | **alt 依存の写真判定**（メタデータだけ見て事実照合した気になる） | **画像本体を目視**で照合する（ナレが指す対象と一致するか・§8 ゲートC） |
| 5 | **channel.yaml 単一 schedule での同時刻予約事故**（複数本が全部同じ日時に予約） | 予約はエピソード別 `frontmatter.publish_at`。channel.yaml の schedule は null 固定（§3・§12） |
| 6 | **非日本ロケ footage の混入**（大阪の駅写真を浅草の説明に等） | 写真は事実そのもの。対象だと確認できたものだけ使い、無ければ図解（§1③・§8） |
