# DOD（Definition of Done）— リファクタリング

> **対象**: 機能変更を伴わないコードの品質改善
> **Contributor がクローズ前にこのチェックリストで完了を判断します**

---

## ✅ 設計・目的

- [ ] リファクタリングの目的（可読性・保守性・パフォーマンス等）が Issue に明記されている
- [ ] 機能変更を含まない（または変更範囲が明確に限定されている）
- [ ] Tech-Lead による影響範囲の分析コメントが存在する

## ✅ 実装

- [ ] 変更ファイル一覧が Implementer のコメントに列挙されている
- [ ] 外部インターフェース（API・型定義・ファイル名等）に変更がない
  - 変更がある場合は移行手順または後方互換性の説明がある
- [ ] コードの意図が改善前より明確になっている

## ✅ テスト（動作保証）

- [ ] 既存テストがすべて通過している（機能の変化がないことを証明）
- [ ] テスト変更がある場合は「テスト自体の改善のみ」であることが明記されている
- [ ] カバレッジがリファクタリング前と同等以上を維持している

## ✅ コードレビュー

- [ ] Reviewer によるレビューが完了し「合格」判定がある
- [ ] 指摘された CRITICAL / HIGH 件数が0件

## ✅ PR・マージ

- [ ] PR が作成されている
- [ ] PR 本文に「リファクタリングの目的・変更の概要・テスト確認結果」が含まれている
- [ ] 人間が PR を承認・マージ済み

---

**完了判定**: 上記すべての項目が ✅ であることを Contributor が確認してから Issue をクローズします。
