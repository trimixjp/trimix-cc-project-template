# v0.24.0 の変更点

このページは、直前バージョン **v0.23.0** から **v0.24.0** までの変更点をまとめたものです。ソースコードのコミット履歴（前回の版バンプコミット `24fe650` 以降）に基づいて記載しています。

---

## 概要

v0.24.0 の主眼は、**導入先プロジェクトのテンプレートを安全に最新化する仕組み**の新設です（Issue #82・親 Epic #80）。

これまで `npm install` で更新されるのは **スキル（`.claude/commands/`）と同梱マニュアルだけ**でした。エージェント定義・ワークフロー・DOD・レビュー判定基準・エスカレーションルールなどは、一度配置されたら永久に古いままで、テンプレート側の改善を受け取る手段がありませんでした。有料商材として販売するうえで、この「更新できない」状態は出荷の妨げになっていました。

v0.24.0 では **`upgrade` コマンド**を新設し、`.claude/` 配下のテンプレート一式を単一コマンドで最新版へ追随できるようにしました。最優先の制約は「**ユーザーがカスタマイズしたファイルを黙って破壊しないこと**」で、上書き前の自動バックアップと、カスタマイズ済みファイルの上書き保護という二重の安全策を備えています。

使い方は [アップグレード](guide/upgrade.html) を参照してください。

---

## 新機能

### `upgrade` コマンドの新設（Issue #82）

`npx @trimix/ai-team upgrade [team_id]` を追加しました。`.claude/` 配下のテンプレート（共通エージェント・チームのエージェント／ワークフロー／DOD／レビュー判定基準・エスカレーションルール・モデルプロファイル・スキル）を最新版へ更新します。`team_id` を省略すると導入済みの全チームが対象になります。

- 既定の動作は「**差分を提示 → ユーザー確認 → バックアップ → 適用**」で、確認なしの一括上書きは行いません
- `--dry` — 差分の提示のみ（書き込み・バックアップとも行いません）
- `--force` — カスタマイズ済みファイル（`# customized: true`）も上書きします
- `--yes` — 確認プロンプトを省略します。非対話環境（CI・パイプ実行）では続行に必須です
- 更新対象は各チームの `plugin.json` の `install` マップから導出します。ファイル種別をハードコードしないため、`content` チームの `compliance-rules/` や `youtube` チームの `PRODUCTION-GUIDE.md` など、チーム固有のファイルも取りこぼしません
- `.github/ISSUE_TEMPLATE/` は `.claude/` 外のリポジトリ設定のため対象外です。黙って落とさず、対象外である旨を実行時に明示します

### アップグレード前の自動バックアップ（Issue #82・追加要件）

`upgrade` は、ファイルを上書きする前に、対象ファイルを **`.ai-team-backups/<YYYYMMDD-HHMMSS>/`** へ元の相対パスを保ったまま退避します。

- 退避後に **SHA-256 を再計算して退避元と一致することを検証**し、`manifest.json` に作成日時・パッケージバージョン・各ファイルのハッシュを記録します
- **バックアップが 1 ファイルでも失敗したら、アップグレードを実行せず終了コード 1 で停止します（fail-closed）**。退避できない状態での上書きは決して行いません
- 復元は `cp -R .ai-team-backups/<日時>/.claude ./` の 1 行で完了します。開始前にバックアップの趣旨、完了後に保存先・復元方法・自動削除されないことを表示します
- 世代ディレクトリは同一秒に複数回実行しても連番（`-2`, `-3` …）で衝突を回避し、先行世代を上書きしません
- バックアップ作成時に `.gitignore` へ `.ai-team-backups/` を冪等に追記します

## バグ修正

### カスタマイズ上書き保護をワイルドカード展開にも適用（データ損失・Issue #82）

`# customized: true` による上書き保護が単一ファイル分岐（`workflow.yml` / `review-config.yml`）にしか実装されておらず、**ワイルドカードで展開される `agents/*` と `dod/*` は `--force` を付けなくてもユーザーのカスタマイズが黙って上書きされていました**（データ損失）。

保護判定を共通関数（`isCustomized`）に切り出し、単一ファイル分岐とワイルドカード分岐（`copyDirAndTrack`）の両方から呼ぶよう統一しました。これにより `agents/` や `dod/` のカスタマイズ済みファイルも、`--force` を指定したときだけ上書きされます。

あわせて、このバグを長期間見逃す原因となっていた既存テスト（テスト内で組み立てた文字列リテラルに `assert` するだけで、実際の配置処理を一度も呼んでいないトートロジー）を、一時ディレクトリ上で実際に配置処理を呼んでファイル内容を検証する形に書き直しました。

## 改善

### スキル配布リストの動的走査化（Issue #82・#27 の積み残し）

配布スキルの一覧を静的なハードコードから、`skills/` ディレクトリを走査して `ai-team-*.md` に一致するファイルを返す方式へ置き換えました。スキルを追加したときに配布リストへの追記を忘れて配置漏れが起きる事故（`ai-team-ticket.md` で実際に発生）を構造的に防ぎます。README など命名規則に合わないファイルは除外されます。あわせて `bin/sync-templates.js` に `skills/ → .claude/commands/` の同期を追加し、開発リポジトリでもドッグフーディングが成立するようにしました。

### sns / youtube のミラーパッケージ追加（Issue #82）

SNS 運用チームと YouTube 動画制作チームのミラーパッケージ（`packages/workflow-sns` / `packages/workflow-youtube`）を、既存 4 チームと同一構造で追加しました。これにより 6 チームすべてが `plugin.json` を持ち、`upgrade` がすべてのチームの更新対象を `install` マップから導出できるようになりました。テンプレート整合性テスト（SHA-256 一致検証）の対象も 4 チームから 6 チームへ拡張しています。

### バージョン更新通知（Issue #82）

導入先プロジェクトの `ai-team-plugins.json` に記録された導入時バージョンと、配布物の `registry.json` の最新バージョンを比較し、差があれば `upgrade` 実行時と `postinstall` 完了時に「更新があります」と通知するようにしました。更新に気づけるようにするための通知で、更新の実行自体は `upgrade` で行います。

---

## 破壊的変更

なし。

`npm install`（`postinstall`）の挙動は従来どおりで、スキルとマニュアルのみを展開します。`upgrade` はユーザーが明示的に実行するコマンドとして追加されたものであり、既存の運用を変更しません。

---

## 既知の制限

- **マーカーの無い手編集ファイルは `upgrade` で上書きされます。** 上書き保護は `# customized: true` マーカーの有無だけで判定するため、マーカーの付かない手編集ファイル（例: `agents/*.md` の `model` / `effort` を直接編集したもの）は上書き対象になります。ただし適用前に必ずバックアップへ退避されるため、復元は可能です。この制限は保護判定をハッシュ照合へ移行する [Issue #85](https://github.com/takufukagawa/trimix-cc-project-template/issues/85) で対応予定です
- `upgrade` / バックアップのテスト堅牢性の改善（実時計依存・対話端末でのハング・壊れた `plugin.json` の未捕捉例外）は [Issue #84](https://github.com/takufukagawa/trimix-cc-project-template/issues/84) で追跡しています
