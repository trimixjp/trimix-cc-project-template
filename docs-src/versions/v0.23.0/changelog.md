# v0.23.0 の変更点

このページは、直前バージョン **v0.22.1** から **v0.23.0** までの変更点をまとめたものです。ソースコードのコミット履歴（前回の版バンプコミット以降・25 コミット）に基づいて記載しています。

---

## 概要

v0.23.0 の主眼は、**全エージェント定義・全スキルの「モデル非依存」ブラッシュアップ**です（Issue #71）。

これまでのエージェント定義は、高い推論能力を持つモデルが行間を補完してくれることを暗黙の前提とした記述（「適切に判断する」「状況に応じて対応する」等）を含んでいました。その結果、実行するモデルによって判断のブレや品質差が生じる余地がありました。

v0.23.0 では、8 本のスキルと 47 体のエージェント定義＋ワークフローを見直し、曖昧な自然文の判断を**決定表・転記式チェック・機械的検証**へ置き換えました。Opus / Sonnet などどのモデルで実行しても、高推論モデルと同等品質で動作することを目指した変更です。

あわせて、v0.22.1 リリース後にマージ済みだった未リリース分の機能改善（バージョン管理の `none` 選択肢・テンプレート同梱チームの install ガード等）も本バージョンに含まれます。

---

## 改善

### エージェント記述標準の新設と全エージェントへの水平展開（Issue #71）

エージェント定義ファイル記述ガイドライン（`.claude/docs/agent-writing-guide.md`）に、次の 4 つの記述標準を新設しました（§9-5〜9-8）。

| 節 | 標準 | 内容 |
|----|------|------|
| §9-5 | 「失敗時挙動」セクションの必須化 | 前提が崩れた場合（ファイル欠落・コマンド失敗・0件検出等）に何をするかを、全エージェントが明文で持つ |
| §9-6 | 機械的検証の原則 | 合否・分岐の判定は、人間の感覚ではなくコマンド出力・正規表現照合など機械的に再現できる基準で行う |
| §9-7 | モデル非依存の原則 | 実行モデルの推論能力に依存する記述（「適切に」「柔軟に」等）を避け、決定表・手順として書き下す |
| §9-8 | 設定値のハードコード禁止 | しきい値・ラベル名等は設定ファイル（workflow.yml・review-config.yml 等）を単一情報源とし、エージェント本文に重複記載しない |

この標準に基づき、共有エージェント（dispatcher / contributor / human-escalator）、バックエンド・フロントエンド・インフラ・コンテンツ・SNS・YouTube の全チームのエージェント定義に「失敗時挙動」セクションを水平展開し、判断基準を決定表化・転記式チェックに統一しました。カスタムチーム作成用のベーステンプレート（`_agent-template.md`）も新標準に対応しています。

### 全スキルへの決定表・失敗時フォールバック・報告前チェックの追加（Issue #71）

8 本のスキル（`/ai-team-setup` / `/ai-team-run` / `/ai-team-watch` / `/ai-team-resume` / `/ai-team-configure` / `/ai-team-install` / `/ai-team-gallery` / `/ai-team-create`）に、分岐判定の決定表・コマンド失敗時のフォールバック手順・ユーザーへの報告前チェックリストを追加しました。スキル実行時の判断も、エージェントと同じくモデルに依存しない決定論的な手順になります。

### SNS 運用チームに品質ゲート（差し戻し）を追加（Issue #71）

SNS 運用チームの `strategist-review` ステップ（Strategist による調査結果確認）に `on_rework` を追加しました。調査レポートが不十分な場合は Researcher へ差し戻して再調査させ、差し戻し上限（`rework_limit: 2`）を超えた場合＝同一 Issue で 3 回目の不合格は human-escalator にエスカレーションします。これまで調査結果の品質を担保するゲートが欠落しており、不十分な調査のまま Writer へ進む余地がありました。

### Tech-Writer の差分範囲判定を多段フォールバック化（Issue #71）

バックエンドチームの Tech-Writer が「どのコミット範囲の変更をドキュメントに反映するか」を決める際の範囲判定を、Version-Bumper と同一の 4 段フォールバック（① git タグ境界 → ② 版バンプコミット境界 → ③ package.json 変更コミット境界 → ④ HEAD 全件）に統一しました。git タグを運用していないリポジトリで履歴全体を誤って対象にしてしまう問題（インシデント #54 と同種）を、ドキュメント更新でも防ぎます。採用した範囲判定方式は完了報告に必ず記録されます。

### フロントエンドチームの起動ラベルを `frontend:designer` に統一（Issue #71）

フロントエンドチームのワークフローは最初のステップが `designer-analysis`（Designer によるデザイン仕様策定）であるため、Issue にワークフローを起動させるためのラベルを `frontend:frontend-lead` から `frontend:designer` に統一しました。対象は `/ai-team-run` のキーワード判定表、`/ai-team-watch`（ソロモード）の `target_labels`、`/ai-team-setup` が生成する `ai-team-config.yml` です。`frontend:frontend-lead` は Frontend-Lead が担当するステップ（要件分析・レビュー方式判断）のラベルとして引き続き使われます。

**既存プロジェクトへの影響**: ソロモードで運用中の場合は、`.claude/ai-team-config.yml` の `solo.target_labels` の `frontend:frontend-lead` を `frontend:designer` に更新してください（更新しない場合、フロントエンド向け Issue が自動検出されません）。

### YouTube チームの director ステップ判定を決定論化（Issue #71）

director が `director-planning`（種別判定）と `director-channel-review`（チャンネル設定レビュー）のどちらのステップで呼ばれたかの判定を、直前工程の引き継ぎコメント（`⏭️ 次のアクション:` 行）を `grep` で機械抽出して決定表と照合する方式に変更しました。`⏭️` 行が存在しない初回起動は `director-planning` で開始します。あわせて、抽出コマンドの失敗・workflow.yml の欠落など前提が崩れた場合の「失敗時挙動」を追加しました。

### バージョン管理の選択肢に「使わない（none）」を追加（Issue #68）

`/ai-team-setup` のバージョン管理の質問に、`auto`（自動インクリメント）・`manual`（手動管理）に加えて **`none`（使わない）** を追加しました。

| 設定値 | 動作 |
|-------|------|
| `auto` | Reviewer 合格後に conventional commit を解析して `package.json` を自動インクリメント |
| `manual` | Version-Bumper ステップは残り、スキップ報告のみ行って Tech-Writer へ引き継ぐ |
| `none` | version-bumper ステップ自体をワークフローから削除。Reviewer 合格後は直接 Tech-Writer へ |

`none` は、バージョン概念のないリポジトリ（アプリ運用・ドキュメントリポジトリ等）に適しています。既存プロジェクトで手動でステップを削除する場合は、`workflow.yml` の reviewer / cross-review の `next: version-bumper` を `next: tech-writer` に付け替えてください。

### テンプレート同梱チーム（sns / youtube）の install ガードと gallery 区別表示（Issue #66）

SNS 運用チームと YouTube 動画制作チームは、プラグインパッケージではなくパッケージ本体のテンプレート（`templates/teams/<id>/`）として同梱・配布されています（`registry.json` の `distribution: "template"`）。この実態に合わせて次を変更しました。

- `/ai-team-install sns` / `/ai-team-install youtube` を実行した場合、プラグインパッケージとしては提供されていない旨の案内メッセージを表示します（導入は `/ai-team-setup` で行います）
- `/ai-team-gallery` では、プラグインとしてインストール可能なチームとは別に「テンプレート同梱（/ai-team-setup で追加）」セクションとして区別表示します
- あわせて、`gh label create` をシェル文字列補間から配列引数（`execFileSync`）に変更し、ラベル説明文のクォート崩れを防ぎました

### `/ai-team-setup` のセットアップウィザード改善（Issue #66・#68）

- チーム選択の質問に YouTube 動画制作チームを追加し、6 チームを 2 回（エンジニアリング・コンテンツ系／マーケティング・メディア系）に分けて確認するようにしました
- テンプレートのコピー手順に共通の実行例（`mkdir -p` → `cp`、パッケージルートの基準）を明記しました

## バグ修正

### postinstall で `ai-team-create.md` が配布されない欠落を修正（Issue #66）

パッケージ導入時（`postinstall`）に `.claude/commands/` へ展開されるスキルファイルの一覧に `ai-team-create.md` が含まれておらず、`/ai-team-create` が導入直後に使えない欠落がありました。配布スキル一覧を `bin/lib/skill-files.js` の `SKILL_FILES` に単一情報源化し、`bin/setup.js` と `bin/postinstall.js` の両方が同じ一覧を参照するように修正しました。展開されるスキルファイルは全 8 件です。

### ensure-issue.sh がハイフン区切りコマンドをブロックする問題を修正（Issue #66）

Issue 強制チェックの hook（`ensure-issue.sh`）が、スペース区切りの `/ai-team <sub>` のみをスルー対象としており、正準表記であるハイフン区切りの `/ai-team-run` 等をブロックしていました。判定の正規表現をハイフン区切りに対応させ、案内メッセージ内のコマンド表記も `/ai-team-run` に修正しました。
